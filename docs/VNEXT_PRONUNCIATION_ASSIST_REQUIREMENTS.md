# Pronunciation Assist vNext — Requirements Freeze

Status: **IMPLEMENTATION PREP / REQUIREMENTS FROZEN**

This document replaces the product meaning of the original A1 zero-pause boundary MVP.
The old A1 evidence remains useful for public VOICEVOX/YMM4 mutation and synthesis routes,
but its product semantics were incomplete.

## 1. Product goal

Voice Quality Assist should let the editor tell VOICEVOX **where a phrase should be split**
without requiring the editor to manually write VOICEVOX accent notation.

The editor supplies:

- phrase boundary intent;
- optional helper-mora intent;
- optional light prosody intent.

VOICEVOX still supplies the normal automatic accent analysis inside each phrase.

The key distinction is:

- Japanese comma `、`: creates a phrase boundary **and keeps its normal pause**.
- direct accent notation such as `/` + `'`: can define a boundary, but requires manual accent editing.
- Voice Quality Assist boundary: creates a phrase boundary **while keeping VOICEVOX automatic accent analysis and removing only the artificial pause**.

## 2. Canonical forced-boundary semantics

### 2.1 Durable marker

The durable project marker remains YMM4's official invisible control tag:

`<w0>`

Reasons:

- YMM4 already hides it from rendered subtitles;
- it survives save/reload;
- ControlTagParser exposes its clean-text position;
- it does not require plugin-private subtitle rendering.

The canonical marker is an internal representation. Users should not be required to type it directly in the final UX.

### 2.2 Required transformation

Given:

`これは、テスト音声です実<w0>験のために生成しました。`

the plugin must derive a transient VOICEVOX analysis input equivalent to:

`これは、テスト音声です実、験のために生成しました。`

The inserted comma is **transient**:

- do not persist it into Serif;
- do not persist it into Hatsuon;
- do not expose it as a normal user comma;
- do not replace original punctuation.

VOICEVOX must analyze the transient comma input normally, so the text on both sides receives ordinary automatic accent analysis.

After VOICEVOX returns the generated pronunciation structure, only the PauseMora that corresponds to the plugin-inserted comma is mutated to:

`VowelLength = 0`

Original commas and their pauses remain untouched.

### 2.3 Observable acceptance example

Baseline example:

Serif:
`これは、テスト音声です実験のために生成しました。`

Observed generated pronunciation:
`コレワ'、テ_ストオ'ンセエデ_ス/ジッケンノ'/タメ'ニ/セエセエ'/シマ'_シタ`

Forced-boundary example:

Serif:
`これは、テスト音声です実<w0>験のために生成しました。`

Expected VOICEVOX analysis shape:
`コレワ'、テ_ストオ'ンセエデ_ス/ジッ、ケンノ'/タメ'ニ/セエセエ'/シマ'_シタ`

Expected final behavior:

- a phrase boundary exists between `実` and `験`;
- accent inside each resulting phrase is generated by VOICEVOX;
- the artificial comma pause is zero length;
- the original comma after `これは` keeps its normal pause;
- `<w0>` is not visible in subtitles;
- neither `<w0>` nor the artificial comma is persisted into Hatsuon.

## 3. Multiple boundaries and identity

Multiple forced-boundary markers are allowed.

The implementation must distinguish:

- punctuation already present in the source;
- punctuation injected by the plugin.

It is forbidden to set all comma PauseMoras to zero.

Every injected boundary must be mapped back to exactly one generated PauseMora.
If a unique mapping cannot be proven, the item fails closed and ordinary audio is preserved/restored according to the runtime safety policy.

## 4. Input UX

### 4.1 User-configurable input token

The user should be able to choose a short input token, for example:

- `|`
- `｜`
- another non-empty token selected by the user.

The token is an **editing convenience**, not the durable format.

When the token is committed as a forced boundary, it is normalized to canonical `<w0>` in Serif.

Requirements:

- canonical project state remains `<w0>`;
- rendered subtitle never shows the boundary token after normalization;
- token replacement must participate in normal YMM4 Undo/Redo;
- token configuration must reject empty strings and unsafe collisions with YMM4 control-tag syntax;
- do not silently reinterpret ordinary text that existed before the feature was enabled.

### 4.2 Minimum fallback UX

If safe automatic token normalization cannot be implemented with public host surfaces,
the first vNext candidate may expose an explicit **Insert forced boundary** action instead.

Do not solve this by intercepting keyboard input through Harmony.

## 5. Pronunciation Assist Effect settings

The current Effect has durable properties but no usable detail editor.
vNext must expose the product concepts in the Effect UI.

Minimum settings:

### Forced accent boundary

- user input token / insertion action;
- explanation that the boundary keeps VOICEVOX automatic accent analysis;
- current forced-boundary count;
- read-only last resolution state when available.

### Helper mora rules

Each rule represents a transient helper inserted for synthesis.

Minimum editable concepts:

- helper text/kana;
- mutation kind:
  - zero vowel length;
  - zero consonant length;
- target insertion boundary / anchor.

The UI must not require editing raw `HelperRulesJson`.
Raw JSON remains a serialization detail.

### Prosody

Expose:

- None
- LightRise
- LightFall
- Hold

Do not expose raw pitch arrays in the MVP UI.

## 6. Effect location

Preferred location:

`VoiceItem -> Audio Effects -> Pronunciation Assist`

The pronunciation assist is voice behavior, not subtitle rendering.

Migration is conditional on real-host validation of the public audio-effect route.

Required Lab proof before product migration:

1. custom AudioEffect appears in VoiceItem Audio Effects;
2. custom properties receive normal property editors;
3. enable/disable notification is observable;
4. settings survive project save/reload;
5. pass-through effect does not alter audio samples;
6. VoiceItem AudioEffects can be enumerated/mutated through a product-acceptable public route;
7. removing/re-adding the effect supports the existing Undo/Redo journal model.

Fallback:

If any required host surface cannot be established without brittle private reflection/Harmony,
keep the durable Effect in the current subtitle-effect collection for this release.
Do not build a fragile audio-effect migration only for UI placement.

## 7. Legacy candidate compatibility

The current candidate stores PronunciationAssistEffect under `JimakuVideoEffects`.

Because no public release has shipped yet, vNext may change the canonical storage location,
but candidate projects should not be destroyed.

Preferred migration policy if Audio Effect is proven:

- **dual-read** legacy subtitle Effect + new audio Effect;
- **new-write** audio Effect only;
- offer/perform one-time migration using public collection APIs;
- copy IsEnabled, HelperRulesJson and Prosody exactly;
- remove legacy Effect only after new Effect is fully configured and attached;
- migration participates in Undo when initiated by a user action;
- save/reload must not duplicate both representations.

If public migration is not safely available:

- continue to read the legacy Effect;
- leave it untouched;
- use the new Effect only for newly configured items.

## 8. Review Bridge / Correction Model meaning

The existing structured operation name `addBoundary` remains valid,
but its product meaning changes to:

> request a forced VOICEVOX automatic-accent phrase boundary at this clean-text position.

It no longer means:

> find an already-existing AccentPhrase boundary and only set its PauseMora to zero.

B1/B2 prompt/help text, previews and documentation must use the new meaning.

The canonical clean-text boundary position remains suitable for B0/B1/B2/B3 identity and review workflows.

## 9. Runtime safety requirements

All existing candidate safety guarantees remain mandatory:

- detached synthesis;
- source revision / lease validation;
- no stale result commit;
- batch/import fingerprint validation;
- destination-safe WAV replacement;
- fail closed;
- normal Undo/Redo;
- disabled/unconfigured item is ordinary YMM4 behavior.

New forced-boundary-specific safety:

- only plugin-injected punctuation pauses may be zeroed;
- source punctuation must not be mutated;
- transient punctuation must not leak into durable Hatsuon;
- ambiguous injected-boundary mapping fails closed;
- multiple markers must map one-to-one;
- source edit during analysis invalidates the result.

## 10. Status / visibility

The user must be able to tell whether a forced boundary was actually accepted.

Minimum runtime states:

- Applied — N forced boundaries resolved;
- No forced boundaries;
- Unsupported provider;
- Analysis mismatch;
- Ambiguous boundary mapping;
- Invalid helper configuration;
- Superseded by newer edit.

The first candidate may surface this in the existing Tool status area.
Per-Effect inline diagnostics are preferred later if the YMM4 property-editor surface supports them cleanly.

## 11. Non-goals for this implementation round

Do not add:

- arbitrary manual VOICEVOX accent notation editor;
- full accent-phrase GUI;
- automatic LLM runtime correction;
- Harmony keyboard interception;
- broad prosody/emotion modeling;
- audio DSP processing.

The feature is intentionally:

**boundary intent + helper intent + small prosody intent, while VOICEVOX keeps automatic accent generation.**
