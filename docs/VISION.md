# Vision / Scope

## 1. Problem

VOICEVOXは通常利用でも十分実用的ですが、動画編集では次の修正が繰り返し発生します。

- 文脈依存の漢字読み
- 固有名詞
- 句境界
- 読点由来の長すぎるpause
- 連続母音など、素直な入力では発声しにくいパターン
- 補助文字を使った発音ハックの再適用
- 初期イントネーションの方向付け

これらを毎VoiceItemで手作業し直すと、修正コストが積み上がります。

## 2. Product goal

目標は「完成した演技を自動生成すること」ではありません。

> **VOICEVOXの初期出力を、編集者が直しやすいスタート地点へ近づける。**

そのために、処理を二層へ分けます。

### Track A — Local Pronunciation Assist

LLMを必要としない、軽量で決定的な補正。

対象例:

- 句境界マーカー
- pause duration = 0
- helper moraのvowel/consonant duration = 0
- 再生成後の宣言的補正の再適用
- 将来の軽量なrelative prosody gesture

### Track B — Voice Review Bridge

文脈を読む必要がある判断をLLMへ渡す、疎結合なReview workflow。

対象例:

- 漢字読み
- 固有名詞
- 文脈による句境界
- 補助文字の候補
- 発声方向の提案

初期版では、YMM4のVoice一覧をExportし、LLMが構造化された修正候補を返し、YMM4でImport・確認して適用する形を優先します。

## 3. Non-goals

初期スコープでは、次を目標にしません。

- VOICEVOXそのものの置き換え
- 常時LLM接続
- 完全自動の演技・感情表現
- ユーザー確認なしの大量破壊的変更
- Serifをプラグイン独自フォーマットへ固定
- 全TTSエンジン同時対応
- Harmony前提の深いホスト改造

## 4. UX principles

### 補助なしでも普通に使える

Effectや補助設定がないVoiceItemは、通常のYMM4として動作すること。

### 編集用の目印は残してよい

制御マーカーは編集時に見える/残ること自体が価値になる場合があります。  
一方、完成字幕では表示させません。

YMM4公式文字制御タグを利用できる場合は、それを優先します。

### 標準編集を邪魔しない

ユーザーがYMM4標準機能でSerifやHatsuonを手修正した場合、その変更を尊重します。

### 失敗時は通常動作へ戻れる

プラグインが無い、Effectを外した、LLM Reviewを使わない、といった状態でもプロジェクトが理解可能であることを重視します。
